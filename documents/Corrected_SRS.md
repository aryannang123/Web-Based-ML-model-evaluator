Actors and Stakeholders
The following actors interact with the system and are defined in the UML Diagram and Use Case Flow document. All role-scoped requirements in this SRS use these actor definitions.

Actor       | Role Description
------------|------------------------------------------------------------------
Student     | Primary user. Uploads datasets, configures and trains models, views and compares evaluation results, and downloads outputs.
Instructor  | Limited reviewer. May view evaluation results explicitly made available for review. Cannot upload datasets, start training, or modify any stored data.
Admin       | Administrator. Manages user accounts, dataset records, and system activity logs. Has access to administrative functions denied to Students and Instructors.
ML Service  | Internal backend component. Executes model training and evaluation when triggered by an authenticated Student request. Not a human actor.

Note: The system shall enforce role distinctions server-side. A user's assigned role (Student, Instructor, or Admin) shall be stored in the user account record and checked by the backend on every protected request. Frontend-only role hiding does not satisfy this requirement (see NFR-4).
